# FB-F1-06 — Fix del harness de integración (correr contra Postgres en CI)

- **ID:** FB-F1-06
- **Fecha:** 19 de junio de 2026
- **Destino:** Claude Code
- **Propósito:** Arreglar el andamiaje de los tests de integración para que corran contra el Postgres plano de CI. El fix es del harness, no de la app.

## Contexto
La suite de integración corrió por primera vez en CI contra Postgres (ya no se saltea). Falló entera, pero por errores de entorno del harness:

- `tests/integration/setup.sql`: la función `uid()` estaba declarada `RETURNS uuid` pero su cuerpo devolvía text (error 42P13). Esto abortaba el setup antes de llegar al DO block de roles.
- Como setup.sql abortaba, los roles mock (`authenticated`, `service_role`) nunca se creaban. `helpers.ts` hacía `SET LOCAL ROLE` y fallaba con "role does not exist".

## Hallazgos corregidos

### Fix 1 — `auth.uid()` devuelve TEXT en vez de UUID (42P13)

**Causa:** El operador `->>` sobre JSONB devuelve TEXT. La función estaba declarada `RETURNS uuid` pero el body retornaba TEXT sin castear. Postgres 14+ valida el tipo de retorno al crear la función.

**Fix en `tests/integration/setup.sql`:**
```sql
-- Antes (devolvía TEXT → 42P13):
SELECT NULLIF(current_setting('request.jwt.claims', true), '')::jsonb ->> 'sub'

-- Después (castea el resultado a UUID):
SELECT (NULLIF(current_setting('request.jwt.claims', true), '')::jsonb ->> 'sub')::uuid
```

### Fix 2 — GRANT de roles al usuario conectado

**Causa:** Aunque el DO block creaba los roles, `SET LOCAL ROLE authenticated` requiere que el usuario conectado sea superusuario O miembro del rol. En CI el usuario es `postgres` (superusuario), pero el GRANT lo hace explícito y defiende entornos no-superusuario.

**Fix en `tests/integration/setup.sql`** — en el DO block:
```sql
DECLARE
  v_user TEXT := current_user;
-- ...
EXECUTE format('GRANT authenticated, anon, service_role TO %I', v_user);
```

## Archivos modificados

- `tests/integration/setup.sql`: fix de uid() + GRANT de roles al usuario conectado.

## No modificado

- Migraciones de la app, policies de RLS, lógica de feature.
- `helpers.ts`, `global-setup.ts`: no requirieron cambio.

## Resultado esperado

Setup.sql se aplica top-to-bottom sin abortar. Roles existen cuando `SET LOCAL ROLE` se ejecuta. La suite de integración corre (no se saltea). Si hay fallas de assertion reales tras el fix, son hallazgos de lógica a reportar por separado.
