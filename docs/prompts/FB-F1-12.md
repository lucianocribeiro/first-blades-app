# FB-F1-12 — Sacar el try/catch silencioso + advisory lock de serialización

- **ID:** FB-F1-12
- **Fecha:** 20 de junio de 2026
- **Destino:** Claude Code
- **Propósito:** Resolver (o, si no, diagnosticar de forma definitiva) las 10 fallas de `mi-perfil.test.ts` contra Supabase real. Solo infraestructura de test. No se toca app, migraciones, funciones, policies ni aserciones de los tests.

## Contexto

FB-F1-11 (`fileParallelism: false` + tripwire) no resolvió: mismas 10 fallas en `mi-perfil.test.ts`, y el tripwire no apareció en el resumen de fallas.

Una segunda revisión en frío detectó un problema que nos tenía debuggeando a ciegas: el `beforeAll` de cada archivo envuelve a `setupTestDb()` en un `try/catch` que, ante cualquier error de setup (incluido el throw del tripwire), imprime un `console.warn` y hace `return` en lugar de fallar. Con eso, un setup roto no rompe el `beforeAll`: los `it(...)` corren igual con `asUser()` contra una base vacía y dan exactamente los mismos síntomas (FK `23503` + lecturas en 0).

Esto deja dos hipótesis vivas:

- **A (concurrencia):** el setup anda bien, pero los archivos se solapan y el `TRUNCATE` de otro archivo borra el seed de `mi-perfil` entre el seed y las aserciones.
- **B (setup que falla en silencio):** `setupTestDb()` tira error, el catch lo tapa, y los tests corren contra una base vacía.

El `try/catch` silencioso es lo que impide distinguirlas.

## Cambios implementados

### (1) Sacar el try/catch silencioso — `mi-perfil.test.ts` y `rls.test.ts`

`purge.test.ts` y `migration.test.ts` ya no tenían try/catch; solo se modificaron los dos archivos que lo tenían.

Patrón antes:
```ts
beforeAll(async () => {
  if (!dbAvailable) return;
  try {
    db = await setupTestDb();
  } catch (err) {
    console.warn('PostgreSQL no disponible — tests de integración omitidos:', (err as Error).message);
    return;
  }
  // ... seed ...
```

Después:
```ts
beforeAll(async () => {
  if (!dbAvailable) return;
  db = await setupTestDb();
  // ... seed ...
```

### (2) Advisory lock de sesión — `tests/integration/helpers.ts`

Constante cerca del tope del archivo:
```ts
const FB_INTEGRATION_LOCK_KEY = 727274;
```

Paso 0 en `setupTestDb()`, justo después de `await client.connect()`:
```ts
  await client.query('SELECT pg_advisory_lock($1)', [FB_INTEGRATION_LOCK_KEY]);
```

### (3) Tripwire (paso 8) — sin cambios

Se conserva tal cual.
