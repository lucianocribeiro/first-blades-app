# FB-F1-15 — Tests de storage.objects contra la Storage API real (retiro del último mock)

**Tipo:** fix + refactor de test (infra de test + workflow CI + devDependency)
**Fase:** 1

## Contexto

Los tests de `storage.objects` fallaban por dos razones:
1. DELETE crudo sobre `storage.objects` → bloqueado por `storage.protect_delete()`.
2. Filas mock en `storage.objects` (INSERT por SQL) conflictuaban con la limpieza vía Storage API.

Solución: retiro del último mock. Los tests ahora usan la Storage API real con clientes autenticados por rol.

## Cambios implementados

### `package.json` + `package-lock.json`
`jsonwebtoken` y `@types/jsonwebtoken` como devDependencies.

### `.github/workflows/ci.yml`
Exporta también `TEST_SUPABASE_ANON_KEY` y `TEST_SUPABASE_JWT_SECRET` desde `supabase status -o env`.

### `tests/integration/helpers.ts`
- Import de `jwt` desde `jsonwebtoken`
- `createStorageAdminClient()`: ahora exportada (antes era interna)
- `mintUserJwt(userId)`: firma un JWT HS256 para el usuario con el JWT secret local
- `storageClientForUser(userId)`: cliente supabase-js autenticado con `Bearer` token para ejercitar RLS vía Storage API
- `ensureDocumentsBucket(admin)`: idempotente, crea el bucket si no existe
- `setupTestDb()` paso 2: llama `ensureDocumentsBucket` antes de `emptyStorageBucket` (orden: ensure → limpiar → seed)

### `tests/integration/rls.test.ts`
- Header actualizado (quita LIMITACIÓN CONOCIDA, actualiza cobertura)
- Imports: agrega `SupabaseClient`, `createStorageAdminClient`, `storageClientForUser`, `ensureDocumentsBucket`
- Elimina el INSERT crudo de mock en el `beforeAll` principal
- Reemplaza el bloque mock de `storage.objects` por bloque con Storage API real:
  - `beforeAll` del describe: siembra objetos con service-role
  - 8 tests: upload propio (OK), upload ajeno (error), list propio (visible), list ajeno (vacío), supervisor NO ve equipo (0004), admin ve todos, empleado NO borra ajeno (persiste), admin borra (desaparece)

### `tests/integration/mi-perfil.test.ts`
- Header actualizado: referencia a `rls.test.ts` para storage
- Bloque `storage.objects: límite de rol para documentos` eliminado (cobertura consolidada en rls.test.ts)
