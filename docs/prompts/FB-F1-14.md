# FB-F1-14 — Fix: credenciales del Supabase local para la limpieza de Storage en tests de integración

**Tipo:** fix (infra de test + workflow CI)
**Fase:** 1

## Causa raíz

FB-F1-13 construía el cliente de limpieza de Storage con `NEXT_PUBLIC_SUPABASE_URL` /
`SUPABASE_SERVICE_ROLE_KEY` hardcodeados o tomados de variables de app, cuya firma JWT
no coincide con la instancia local que levanta `supabase start` en el runner CI
→ `StorageApiError: signature verification failed`.

## Cambios implementados

### `.github/workflows/ci.yml`

Paso nuevo entre "Levantar Supabase local" y "Tests de integración RLS":

```yaml
- name: Exportar credenciales del Supabase local
  run: |
    set -euo pipefail
    eval "$(supabase status -o env)"
    echo "TEST_SUPABASE_URL=${API_URL}" >> "$GITHUB_ENV"
    echo "TEST_SUPABASE_SERVICE_ROLE_KEY=${SERVICE_ROLE_KEY}" >> "$GITHUB_ENV"
```

`supabase status -o env` emite variables del Supabase local post-start; `eval` hace el
quoting correcto antes de reemitir valores limpios a `$GITHUB_ENV`. Las variables usan
el prefijo `TEST_*` para no colisionar con las de app. Se eliminaron las claves
hardcodeadas del paso de tests.

### `tests/integration/helpers.ts`

- Eliminadas las constantes `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY`.
- `createStorageAdminClient()`: falla fuerte con mensaje claro si faltan las dos vars
  `TEST_SUPABASE_URL` / `TEST_SUPABASE_SERVICE_ROLE_KEY`.
- `emptyStorageBucket()`: tolera bucket inexistente ("not found" en el mensaje del
  error de `list`); propaga cualquier otro error.
- `setupTestDb()` paso 2: `await emptyStorageBucket(createStorageAdminClient(), 'documents')`.

### `.env.example`

Documentadas las dos variables nuevas de test con comentario de que salen de
`supabase status`.
